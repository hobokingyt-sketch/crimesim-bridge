# Project Armor I: repository audit

Audited base: `56589ae4858da3809de2ef637fda4b72d17ebdc4`.
The local audit tree was compared to GitHub tree `b4c2287a623f257bcda3813139ceedbb8b18918f`.

## Finding
The source is already separated into Rust core modules and a small web UI. A disruptive directory
rewrite is not justified. The missing layer is a low-cost entry route, explicit module ownership,
limited handoffs, an honest current checkpoint and a discoverable record of unfinished safety work.

Earlier documentation describes intended protection more strongly than the code supports.
`update.rs::rollback` and initialization do not use the update journal. `fsops.rs::atomic_write`
removes a destination before renaming. `update.rs::apply` discards recovery errors. Integer history
folders can be reused after rollback with different contents. `godot.rs` child commands have no
parent-enforced deadline, and ZIP/path handling lacks several adversarial checks. The initial model
scripts exercise simplified models or search source strings; they are not Rust crash-injection tests.

CI uses a root Cargo workspace but points caching/installer collection at `src-tauri/target`.
There is no committed Cargo.lock. These need evidence-backed fixes, not a declaration of completion.
The real Windows E2E was observed passing on run 35690061931 during this audit; that does not establish
installed-UI correctness, final installer delivery or the full crash-safety claims.

## This pass
Adds task-scoped repository memory/tooling and records acceptance tests for remaining work. Existing
Rust modules and the Windows build workflow are intentionally unchanged. Runtime-risk repairs follow
as separate small passes, beginning with SAFE-1. No new gameplay or hidden platform integration.
